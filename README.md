# A/B-тестирование алгоритма ранжирования ленты (Python)

## Бизнес-контекст
Продукт - развлекательное приложение с лентой коротких видео. Команда ML разработала новый алгоритм ранжирования контента. 
**Гипотеза:** улучшенная персонализация позволит увеличить вовлеченность пользователей (долю успешных сессий, в которых просмотрено 4 и более страниц).
**Задача:** спланировать дизайн эксперимента, проверить чистоту собранных данных и статистически оценить влияние нового алгоритма на целевую метрику.

## Стек технологий
* **Язык и библиотеки:** Python (Pandas, Matplotlib), `statsmodels`.
* **Дизайн эксперимента:** оценка базовой конверсии, расчет MDE (3%), уровня значимости (α=0.05) и мощности (1-β=0.8) для определения размера выборки и длительности теста.
* **Статистический критерий:** Z-test для разности пропорций (`proportions_ztest`).

## Ключевые этапы и результаты

### 1. Планирование теста
На основе исторических данных EDA показал, что базовый уровень целевой метрики составляет ~31%. Расчет через `NormalIndPower` выявил необходимость собрать по 41040 пользователе в каждую группу. Учитывая среднюю дневную посещаемость (DAU), длительность эксперимента составила 9 дней.

### 2. Валидация данных
* Размер групп A и B отличается менее чем на 1% (допустимая погрешность);
* Пересечений пользователей между контрольной и тестовой группами не обнаружено;
* Распределение по ОС (iOS/Android/PC) и регионам идентично в обеих выборках.

### 3. Статистический вывод
* Группа A: 31.57% успешных сессий.
* Группа B: 31.47% успешных сессий.
* P-value: 0.578 (при α = 0.05).

## Итоговая рекомендация
Разница между группами составила статистически незначимые -0.11% по абсолютной шкале. У нас нет статистических оснований отклонить нулевую гипотезу. 
Решение: отказаться от нового алгоритма для всех пользователей. Обновление не доказало своей эффективности в повышении вовлеченности (глубины просмотра). Рекомендуется отправить алгоритм на доработку или использовать старый.
